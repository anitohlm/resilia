## Slide 3: Brief about the idea
- **Header:** Google Cloud | H2S — AI Builder Cup: Build in JAPAC. Build for the world.
- **Slide Title:** Brief about the idea
- **Subtitle:** AI-Assisted Community Disaster Coordination Operating Under Severe Network Degradation
- **Key Points:**
  - **The 72-Hour Blackout Crisis:** Severe climate disasters knock out electrical grids and drown cellular base stations across vulnerable river basins (Marikina River). Conventional cloud-only tools fail with blank loading spinners during the critical first 72 hours.
  - **Hybrid Dual-Engine AI Innovation:** Combines Google Gemini 3.8 Flash in the cloud for deep situational reasoning and predictive clustering with zero-cloud-overhead edge persistence (15 IndexedDB stores) and deterministic local algorithms when connectivity drops.
  - **Tri-Role Community Coordination:** Tailored mobile workflows for Residents (instant offline SOS & shelter locator), Responders (START triage tagging & QR wristbands), and Coordinators (incident verification & dispatch gate).
  - **Anti-Hallucination Emergency Safety:** Strict deterministic boundaries grounded in Philippine NDRRMC and DOH disaster SOPs, requiring human coordinator cryptographic authorization for emergency dispatches.
  - **Rigorous Baseline Verification:** Evaluated against simulated Marikina River Basin telemetry (Typhoon Ondoy / Ulysses baselines, Alarm Level 3 at 18m water depth) backed by automated test validation.
- **Speaker Script:**
  > "Every modern disaster management tool makes one fatal assumption: that the internet will work. But in climate-vulnerable regions across JAPAC, cell towers drown and power lines snap. Resilia bridges this gap with a hybrid architecture: leveraging Google Gemini 3.8 Flash in the cloud for deep situational intelligence, while executing deterministic algorithms locally on edge devices so life-saving coordination never stops."

## Slide 6: Process flow diagram or Use-case diagram
- **Header:** Google Cloud | H2S — AI Builder Cup: Build in JAPAC. Build for the world.
- **Slide Title:** Process flow diagram or Use-case diagram
- **Five-Stage Emergency Lifecycle:**
  - **Stage 1: Incident Ingestion (Edge):** Citizen triggers SOS or river telemetry hits Alarm Level 3 (18.0m). Event instantly committed to local IndexedDB.
  - **Stage 2: Dual-Engine AI Triage:** Cloud mode clusters spatial reports via Google Gemini 3.8 Flash; Edge mode computes deterministic 0-100 vulnerability score offline.
  - **Stage 3: Incident Commander Authorization:** Human Coordinator reviews structured triage evidence, inspects shelter capacity, and signs digital dispatch.
  - **Stage 4: Field Responder Execution:** Mobile rescue teams receive mission route, navigate offline, execute START triage tagging, and assign QR wristbands.
  - **Stage 5: Shelter Intake & Idempotent Sync:** Evacuees check in via QR, receive relief kits with 24h cooldown; Sync Agent pushes records to Cloud Run when uplink blinks on.
- **Speaker Script:**
  > "Our process flow diagram maps the complete disaster lifecycle across five stages. When a citizen reports an emergency or river sensors trigger Alarm Level 3, the event is immediately committed to local memory. Gemini clusters incidents online, while local rules compute vulnerability scores. Crucially, a human coordinator must authorize the dispatch, after which responders execute field triage and shelter teams log aid distribution."

## Slide 8: Architecture diagram of the proposed solution
- **Header:** Google Cloud | H2S — AI Builder Cup: Build in JAPAC. Build for the world.
- **Slide Title:** Architecture diagram of the proposed solution
- **Architectural Tiers:**
  - **Cloud Intelligence Tier (Google Cloud Platform):**
    - Google Gemini 3.8 Flash via `@google/genai` (multi-modal situation synthesis, macro clustering, spatial resource allocation).
    - Google Cloud Run (containerized serverless microservices backend).
    - Google Cloud Firestore (distributed transactional document datastore).
    - Google Maps Platform (geospatial mapping and shelter routing).
  - **Edge Resilience Tier (Browser PWA & Mesh Nodes):**
    - Browser IndexedDB (15 versioned object stores, <15ms write latency).
    - Local Deterministic Agent Orchestrator (zero-cloud offline rule execution).
    - Service Worker (Workbox asset pre-caching for 100% offline boot).
  - **Bi-Directional Synchronization Tier:**
    - Idempotent Sync Agent with UUID transaction journal, SHA-256 conflict hashes, and exponential backoff health probing.
- **Speaker Script:**
  > "Resilia's architecture pairs Google Cloud with resilient edge execution. In the cloud, Gemini 3.8 Flash and Cloud Run provide situational intelligence and city-wide synchronization. At the edge, a Progressive Web App powered by 15 IndexedDB stores executes deterministic triage and inventory rules. When connectivity drops, edge operations continue seamlessly; when restored, idempotent sync merges all records."
